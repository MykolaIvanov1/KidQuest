# KidQuest 🤖⭐

Сімейний PWA-застосунок українською мовою. Перетворюємо щоденні справи на захопливі пригоди.

Головне джерело вимог — [технічне завдання](KIDQUEST_TECHNICAL_SPECIFICATION.md). Реалізовано основу проєкту, авторизацію та другий етап: CRUD квестів і нагород, виконання з фото, перевірку батьками й транзакційний журнал балів.

## Структура

```text
frontend/            React + TypeScript + Vite
backend/             Express + TypeScript, модулі API
packages/types/      Спільні типи відповідей
packages/validation/ Спільні Zod-схеми
packages/shared/     Спільні утиліти
prisma/              Схема, початкова міграція та seed
docs/                Архітектура, запуск, межі етапу
scripts/             Допоміжні команди розробника
docker-compose.yml   Локальна PostgreSQL
```

Назви `frontend/` та `backend/` відповідають прямому запиту користувача; це відповідники `apps/web/` та `apps/api/` із ТЗ. Розподіл відповідальності monorepo та спільних пакетів збережено.

## Швидкий запуск на Windows

Потрібні Node.js 22.12+ і pnpm 11.25.0, Docker Desktop із Linux containers. Відкрийте PowerShell у корені репозиторію:

```powershell
pnpm install
pnpm setup:env
docker compose up -d
pnpm db:generate
pnpm db:deploy
pnpm dev
```

`setup:env` генерує локальні секрети й не перезаписує наявний `.env`. Не додавайте `.env` до Git. Відкрийте [KidQuest](http://localhost:5173), зареєструйте батьківський акаунт і створіть обліковий запис дитини з панелі сім'ї. Дитина входить за власними email і паролем. Батьки мають однакові права; у сім'ї допускаються два батьківські акаунти.

Докладніше: [запуск на Windows](docs/setup-windows.md), [перший етап](docs/phase-1.md), [другий етап і API](docs/phase-2.md), [база даних](docs/database.md).

Після входу батьки створюють категорію та квест у розділі «Квести», а нагороду — у «Нагородах». Дитина позначає квест виконаним і за потреби додає фото. Після перевірки на батьківській панелі бали з’являються в балансі. Запит нагороди не списує бали: списання відбувається при підтвердженні батьками, а видача завершує запит без додаткового списання.

Фото зберігаються у приватній директорії `STORAGE_PATH` (за замовчуванням `storage/` у корені). Дозволено до п’яти JPEG/PNG/WebP, до 5 МіБ кожне; backend перевіряє вміст і оптимізує зображення. Доступ до фото потребує авторизації та належності до сім’ї. Для збереження даних потрібні резервні копії як PostgreSQL, так і файлової директорії.

## Перевірки

```powershell
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test
pnpm build
```

Тести не потребують Firebase або AI-ключів. Інтеграційні тести з PostgreSQL використовують окрему тестову базу; не вказуйте їм базу з сімейними даними. Після налаштування `DATABASE_TEST_URL` команда `pnpm db:test` додатково перевіряє п'ять обмежень схеми із повним відкатом тестових записів.

## Наступний етап

Streak, досягнення, календар, push-сповіщення, повна офлайн-синхронізація та окремий AI-модуль Квестика відповідно до ТЗ. Наявність таблиць цих модулів у схемі не означає, що відповідні бізнес-процеси вже реалізовані. Встановлення PWA на реальному телефоні потребує окремої перевірки.
