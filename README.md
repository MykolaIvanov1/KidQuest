# KidQuest 🤖⭐

Сімейний PWA-застосунок українською мовою. Перетворюємо щоденні справи на захопливі пригоди.

Головне джерело вимог — [технічне завдання](KIDQUEST_TECHNICAL_SPECIFICATION.md). Реалізовано основу проєкту, авторизацію, CRUD квестів і нагород, виконання з фото, перевірку батьками й транзакційний журнал балів, гейміфікацію, сповіщення з підтримкою Firebase Cloud Messaging та налаштування акаунтів, офлайн-перегляд і чергу виконань із фото, модуль Квестика з локальними підказками, браузерні E2E-тести, production-конфігурацію Docker/Caddy та ручне резервне копіювання БД і фото.

## Структура

```text
frontend/            React + TypeScript + Vite
backend/             Express + TypeScript, модулі API
packages/types/      Спільні типи відповідей
packages/validation/ Спільні Zod-схеми
packages/shared/     Спільні утиліти
prisma/              Схема, міграції та seed
docs/                Архітектура, запуск, межі етапу
scripts/             Допоміжні команди розробника
docker-compose.yml   Локальна PostgreSQL
docker-compose.prod.yml PostgreSQL + міграції + API + Caddy для сервера
e2e/                 Браузерні сценарії Chromium/WebKit
```

Назви `frontend/` та `backend/` відповідають прямому запиту користувача; це відповідники `apps/web/` та `apps/api/` із ТЗ. Розподіл відповідальності monorepo та спільних пакетів збережено.

## Швидкий запуск на Windows

Потрібні Node.js 22.12+ і pnpm 11.25.0, Docker Desktop із Linux containers. Відкрийте PowerShell у корені репозиторію:

```powershell
pnpm install
pnpm setup:env
docker compose up -d
pnpm db:generate
pnpm db:deploy
pnpm dev
```

`setup:env` генерує локальні секрети й не перезаписує наявний `.env`. Не додавайте `.env` до Git. Відкрийте [KidQuest](http://localhost:5173), зареєструйте батьківський акаунт і створіть обліковий запис дитини з панелі сім'ї. Дитина входить за власними email і паролем. Батьки мають однакові права; у сім'ї допускаються два батьківські акаунти.

Докладніше: [запуск на Windows](docs/setup-windows.md), [перший етап](docs/phase-1.md), [другий етап і API](docs/phase-2.md), [гейміфікація, календар і прогрес](docs/phase-3.md), [сповіщення та підключення Firebase](docs/phase-4.md), [профіль і налаштування акаунтів](docs/phase-5.md), [офлайн-режим і синхронізація](docs/phase-6.md), [Квестик і модуль AI](docs/phase-7.md), [база даних](docs/database.md), [E2E та production-підготовка](docs/phase-8.md), [сервер](docs/production.md), [резервні копії](docs/backup.md), [QA Android/iPhone](docs/mobile-qa.md).

Після входу батьки створюють категорію та квест у розділі «Квести», а нагороду — у «Нагородах». Дитина позначає квест виконаним і за потреби додає фото. Після перевірки на батьківській панелі бали з’являються в балансі. Запит нагороди не списує бали: списання відбувається при підтвердженні батьками, а видача завершує запит без додаткового списання.

Для квесту можна вказати дату початку й дату завершення включно, а також щоденний час виконання. Порожні дати не обмежують період. Доступність для дитини визначається за часовою зоною сім’ї. Після оновлення наявного проєкту виконайте `pnpm db:generate` та `pnpm db:deploy`, потім перезапустіть сервери.

«Повторювати щодня» увімкнено за замовчуванням: створіть квест один раз, і щодня для нього буде доступне окреме виконання. Для повторення безстроково залиште кінцеву дату порожньою. Вимкніть повторення, якщо квест потрібно виконати один раз. Відкритий застосунок оновлює квести при зміні дня; кожне нарахування балів потребує перевірки батьками.

Фото зберігаються у приватній директорії `STORAGE_PATH` (за замовчуванням `storage/` у корені). Дозволено до п’яти JPEG/PNG/WebP, до 5 МіБ кожне; backend перевіряє вміст і оптимізує зображення. Доступ до фото потребує авторизації та належності до сім’ї. Для збереження даних потрібні резервні копії як PostgreSQL, так і файлової директорії.

## Перевірки

```powershell
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test
pnpm test:tooling
pnpm build
```

Тести не потребують Firebase або AI-ключів. Інтеграційні тести з PostgreSQL використовують окрему тестову базу; не вказуйте їм базу з сімейними даними. Після налаштування `DATABASE_TEST_URL` команда `pnpm db:test` додатково перевіряє дванадцять обмежень схеми із повним відкатом тестових записів.

Браузерні тести використовують окрему `DATABASE_E2E_URL` у `.local/e2e-db.env`, ізольовані порти 4100/5180 і синтетичні фото. Інструкція створення тестової БД — у [phase-8.md](docs/phase-8.md).

```powershell
pnpm test:e2e:install
pnpm test:e2e
```

## Наступні перевірки

Потрібно запустити й перевірити Linux-образи після відновлення Docker Engine, налаштувати серверний домен/HTTPS і виконати QA на фізичних Android та iPhone. Для реальної доставки push потрібна конфігурація Firebase. Квестик залишається локальним без зовнішнього AI-провайдера за погодженим рішенням.

Production-запуск і резервне копіювання описані в [production.md](docs/production.md) та [backup.md](docs/backup.md); підготовка конфігурації не означає, що сервер уже опубліковано.

Сповіщення про квести, перевірки, досягнення та нагороди зберігаються в застосунку незалежно від Firebase. Відкрийте дзвіночок у верхній панелі. Щоб отримувати push, заповніть Firebase-змінні в `.env`, перезапустіть застосунок і натисніть «Увімкнути push-сповіщення». Покрокова інструкція — у [документації сповіщень](docs/phase-4.md). Push надсилаються окремою чергою; недоступність Firebase не скасовує виконання чи нарахування балів.

Дитина бачить свій акаунт у «Профілі», батьки керують сімейними акаунтами в «Налаштуваннях». Зміна email, ролі або скидання пароля дитини потребує поточного пароля батьків і завершує сесії зміненого акаунта. Паролі не відображаються. Журнал входів доступний лише батькам. Перед запуском після оновлення застосуйте нові міграції командами `pnpm db:generate` та `pnpm db:deploy`.

Дитячі завдання, нагороди та історія зберігаються в IndexedDB через Dexie. Після попереднього входу й завантаження даних дитина може повторно відкрити production-версію без мережі та зберегти виконання з фото. Черга автоматично надсилається у відкритому застосунку після відновлення зв’язку; закритий браузер не гарантує фонове надсилання. Початкова дата виконання зберігається, а зміна квесту на сервері дає явний конфлікт. Бали завжди нараховують після перевірки батьки. Вихід очищає локальні дані й ненадіслані фото. Докладніше — [офлайн-режим](docs/phase-6.md).

Квестик доступний на головній панелі обох ролей та біля дитячого квесту. Дитина отримує підтримку й прості кроки виконання; батьки — огляд прогресу, ідеї завдань і нагород. Поради запускаються явною дією, не створюють квести та не змінюють бали. За замовчуванням використовуються позначені локальні підказки без зовнішнього сервісу. За погодженим рішенням зовнішнього провайдера зараз не підключаємо. Якщо це рішення зміниться, знадобляться серверний адаптер та ключ; саме заповнення AI_API_KEY цього не вмикає. Докладніше — [Квестик](docs/phase-7.md).
