# Квестик: помічник для дитини та батьків

Модуль відповідає розділу 9 ТЗ та готує інтеграцію AI окремо від основних сімейних операцій. Квестик підтримує дитину, допомагає розбити квест на прості кроки, коментує підтверджений прогрес, пропонує батькам ідеї квестів і нагород. У нього немає прав створювати завдання, підтверджувати виконання, змінювати баланс або видавати нагороди.

## Поточний режим

За замовчуванням працюють локальні українські підказки, сформовані backend за перевіреними даними. Інтерфейс явно позначає їх як локальні; вони не видаються за відповіді нейромережі. Провайдер зовнішнього AI ще не обраний і зовнішні запити не виконуються. Значення `AI_API_KEY` саме по собі не вмикає інтеграцію.

Для зовнішньої моделі визначено серверний інтерфейс `AiProvider`: він отримує обмежений контекст та `AbortSignal`, повертає повідомлення й короткі поради. Адаптер провайдера передається через `DomainDependencies.ai.provider` у `createApp`. Це інтерфейс для реалізації інтеграції, а не готове підключення до конкретного сервісу. Для живих відповідей потрібні вибір провайдера й моделі, його серверний API-ключ та налаштування адаптера. Секрети не повинні бути у `VITE_*`, браузерному коді або Git.

## Інтерфейс

Картка Квестика доступна на головній панелі обох ролей. Дитина може обрати привітання, підтримку або пораду щодо успіхів, а з картки квесту — допомогу із завданням. Батьки можуть запросити огляд прогресу, ідеї квестів або нагород. Відкриття панелі саме по собі нічого не генерує: потрібна явна дія користувача.

Вільного чату, історії розмов, нового пункту навігації та автоматичного застосування рекомендацій немає. Поради залишаються в пам’яті поточної панелі й очищуються при зміні акаунта чи контексту; вони не додаються до IndexedDB. Без мережі показується загальна локальна підказка. Для нових порад на основі актуальних даних потрібен доступний backend.

## API

`POST /api/v1/ai/advice`, JSON:

```json
{ "intent": "MOTIVATE" }
```

Для допомоги з квестом:

```json
{ "intent": "TASK_HELP", "taskId": "UUID_КВЕСТУ" }
```

Для батьківського огляду певної дитини:

```json
{ "intent": "PROGRESS", "childId": "UUID_ДИТИНИ" }
```

Підтримувані дії дитини: `GREETING`, `MOTIVATE`, `PRAISE`, `TASK_HELP`. Дії батьків: `PROGRESS`, `QUEST_IDEAS`, `REWARD_IDEAS`. `taskId` потрібний лише для `TASK_HELP`; `childId` дозволений лише для батьківських дій і повторно перевіряється в межах сім’ї. Без нього backend обирає першу доступну дитину за тим самим правилом, що решта застосунку. Дані кількох дітей не об’єднуються довільно.

Запит проходить JWT, актуальну версію сесії, перевірку ролі, origin і сувору Zod-валидацію. Не можна надіслати довільний prompt, власний context, familyId чи підмінити роль. Окремий ліміт — 20 запитів за хвилину для авторизованого користувача.

Успішна відповідь містить `intent`, `message`, `tips`, `source` (`LOCAL` або `AI`), `reason` (`LOCAL_MODE`, `PROVIDER_UNAVAILABLE` або `null`) і `generatedAt`. Немає API для застосування відповіді до сімейних даних.

## Контекст і відмови

Repository читає лише доступні поточному користувачу сімейні дані. Провайдер отримує агреговані числа: кількість доступних квестів і нагород, підтвердження, очікування перевірки, зароблені бали, баланс і досягнення. Тільки для `TASK_HELP` додається обмежений опис вибраного доступного квесту. Контактні дані й посилання в цьому тексті фільтруються; довільний опис завдання все одно слід вважати недовіреним вмістом, а не інструкціями для моделі.

Провайдер не отримує Prisma Client, довільні SQL-запити, облікові дані, окремі поля ідентифікаторів користувачів, сім’ї чи імен, фото, журнали входів або повну історію. Застосунок не зберігає текст запиту чи відповіді в логах. Контекст не є повною гарантією анонімізації довільного тексту; при майбутньому підключенні сервісу потрібно врахувати його правила роботи з дитячими даними.

Відповідь провайдера перевіряється на структуру, розмір і недозволену розмітку/посилання, а у frontend відображається звичайним текстом. Таймаут провайдера — 8 секунд за замовчуванням. Помилка, таймаут або некоректна відповідь дають локальну підказку з відповідною позначкою. Авторизаційні помилки та недоступний квест не маскуються під успішну пораду. Збій AI не скасовує виконання квесту, фото, синхронізацію чи транзакцію балів.

## Перевірка

```powershell
pnpm --filter @kidquest/backend exec vitest run tests/ai-service.test.ts tests/ai.integration.test.ts
pnpm --filter @kidquest/frontend exec vitest run src/test/ai.test.tsx
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test
pnpm build
```

HTTP-тести використовують окрему `DATABASE_TEST_URL`. Живого AI-провайдера вони не викликають: тестовий адаптер дозволяє перевірити контекст, недоступність, затримки й некоректні відповіді без передачі сімейних даних зовнішньому сервісу.

## Результати перевірок

Усі **471 тест** пройшли: 45 спільної валідації, 255 backend та 171 frontend. Для Квестика додано 30 перевірок сервісу й фільтрації, 13 HTTP/PostgreSQL-сценаріїв та 12 перевірок інтерфейсу. Окремо перевірено, що скасування запиту при закритті панелі не змінює стан зв’язку застосунку. TypeScript, ESLint, Prettier, перевірка Git diff та production-збірка пройшли.

У браузері перевірено вхід дитини, відкриття панелі явною дією та локальну пораду з фактичним числом підтверджених виконань. На ширині 320 px горизонтального переповнення немає; кнопки дій мають висоту щонайменше 44 px. Живі відповіді зовнішнього провайдера не перевірялись, оскільки його не підключено.

- Змінено спільні типи й валідацію у `packages/types/src/index.ts` та `packages/validation/src/index.ts`, реєстрацію API у `backend/src/app.ts`.
- Змінено `frontend/src/pages/DashboardPage.tsx`, `frontend/src/features/quests/TaskList.tsx` та обробку скасування запиту у `frontend/src/services/api.ts`.

## Наступні роботи

Підключення обраного зовнішнього AI-провайдера залишається окремим налаштуванням. Далі — production-підготовка та фінальна перевірка на фізичному телефоні: HTTPS, автономний запуск встановленої PWA, обмеження мобільного сховища та реальна доставка FCM. Ці перевірки не підтверджуються unit-тестами.
