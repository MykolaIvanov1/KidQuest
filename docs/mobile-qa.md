# Перевірка KidQuest на телефоні

Це відтворюваний ручний QA після підготовки HTTPS-стенда. 26.10.2026 користувач підтвердив, що KidQuest добре працює на Android та iPhone через тимчасове HTTPS-посилання. Після виконання запропонованого офлайн-сценарію користувач також підтвердив його успіх на обох платформах: запуск з іконки без мережі, збереження виконання з фото, подальшу синхронізацію та одноразове нарахування після перевірки. 27.10.2026 користувач підтвердив успішне надання дозволу й увімкнення push на Android та iPhone. Доступ до камери та фактична доставка FCM окремо ще не підтверджені. Емуляція viewport у Playwright не замінює ці перевірки. Зовнішній AI-провайдер залишається вимкненим; тестують локальні підказки Квестика.

## Підготовка

Потрібні Android із актуальним Chrome та iPhone із актуальним Safari, HTTPS-адреса, доступна з кожного пристрою, і окрема тестова сім’я з батьківським та дитячим акаунтами. Вкажіть модель, версію ОС, браузера, дату та мітку збірки. Тестові фото не повинні містити приватних сімейних даних.

Адреса `localhost` телефона належить самому телефону. Звичайний HTTP за локальною IP-адресою не дає потрібного захищеного контексту для service worker/FCM. Для push також потрібна узгоджена серверна й публічна Firebase-конфігурація та VAPID; налаштування описано в [phase-4.md](phase-4.md). FCM Web вимагає HTTPS і браузерних API для service worker, push та notifications. [Вимоги Firebase](https://firebase.google.com/docs/cloud-messaging/web/get-started).

Проведіть основний сценарій спочатку онлайн, потім офлайн. Для перевірки приватності використовуйте ще одну окрему тестову сім’ю. Не очищайте сховище й не видаляйте PWA до перевірки синхронізації: це видаляє ненадіслані фото й виконання.

## Тимчасове HTTPS-посилання без власного сервера й домену

Для телефонного QA можна використати Cloudflare Quick Tunnel: він надає тимчасову HTTPS-адресу `trycloudflare.com` для застосунку на цьому комп’ютері без власного домену й акаунта Cloudflare. Адреса працює, поки запущений процес тунелю; сервіс не гарантує постійної доступності. Це режим розробки й тестування. [Офіційна інструкція Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

Спочатку відкрийте Docker Desktop. У PowerShell із кореня KidQuest запустіть:

```powershell
pnpm mobile:start
```

Команда збирає окремий тестовий проєкт і після перевірки готовності показує HTTPS-посилання для телефона. Перший запуск створює нову порожню тестову БД. Перевірити поточний стан і адресу можна командою:

```powershell
pnpm mobile:status
```

Завершити роботу стенда:

```powershell
pnpm mobile:stop
```

Зупинка зберігає серверну БД та фото. Наступний `pnpm mobile:start` використовує ці самі дані; після нового запуску тунелю адреса змінюється й автоматично узгоджується з API. Якщо стенд уже працює, `mobile:start` повертає чинне посилання. Зміна адреси не переносить локальне сховище встановленої PWA, як пояснено нижче.

Для цього запуску готують окремий мобільний Docker-проєкт із новою тестовою БД; основні сімейні дані та фотографії до нього не копіюють. Використовуйте поточне посилання, надане в чаті після запуску стенда. Саме посилання й облікові дані не записують до Git. Комп’ютер, Docker Desktop і тунель мають працювати під час входу, перевірки батьками та синхронізації.

1. Відкрийте те саме поточне HTTPS-посилання на Android у Chrome та на iPhone у Safari. Стенд доступний через публічне посилання, тому створюйте тестові акаунти й використовуйте фото без особистих даних.
2. На батьківському телефоні натисніть реєстрацію та створіть **нову тестову сім’ю** зі своїми тестовими email і паролем. Попередній вхід із `localhost` належить іншому середовищу.
3. Через батьківську панель створіть дитячий акаунт. На другому телефоні відкрийте те саме посилання й увійдіть його email і паролем. Для дитини використовуйте вхід до створеного акаунта; окрема реєстрація створить іншу сім’ю.
4. Батьками створіть категорію та щоденний квест із вимогою фото. Встановіть PWA на обох телефонах за інструкціями нижче, увійдіть кожен у свою роль і дочекайтеся завантаження даних дитини.
5. На дитячому телефоні ввімкніть авіарежим із вимкненим Wi-Fi. Збережіть виконання з тестовим фото, закрийте PWA й відкрийте її з іконки без мережі. Виконання має залишитися в локальній черзі; бали ще не додаються.
6. Відновіть мережу й залиште дитячий PWA відкритим. Дочекайтеся надсилання. Батьками перевірте **одне** виконання з фото й підтвердьте його; нарахування має бути одним, навіть після оновлення екрана. Запишіть фактичний результат окремо для Android та iPhone.

Після нового запуску Quick Tunnel hostname змінюється. Інша адреса має окремі браузерні cookies, Service Worker та офлайн-сховище: стара встановлена іконка продовжує посилатися на стару адресу, а ненадіслані фото не переносяться автоматично. До планового перезапуску тунелю завершіть синхронізацію за старою адресою. Після зміни відкрийте нове посилання, увійдіть і встановіть PWA заново; стару іконку й дані видаляйте після перевірки відправлення черги. Актуальну адресу також потрібно узгодити з FRONTEND_URL мобільного API під час підготовки стенда.

За замовчуванням Firebase на тимчасовому стенді вимкнений. Явне підключення виконується через `pnpm setup:firebase` та `pnpm mobile:firebase` за [інструкцією Firebase](firebase-setup.md); реальну доставку push перевіряють окремо. Встановлення PWA та офлайн-сценарій на Android/iPhone підтверджені користувачем 26.10.2026. 27.10.2026 користувач підтвердив дозвіл і ввімкнення push на обох телефонах; доступ до камери та фактична доставка системних повідомлень ще потребують окремого підтвердження.

## Встановлення PWA

### Android / Chrome

1. Відкрийте HTTPS-адресу у Chrome й дочекайтеся завантаження.
2. У меню Chrome виберіть установлення вебдодатка: назва може бути «Установити й створити ярлик» → «Установити».
3. Запустіть KidQuest з іконки. Перевірте назву, іконку, українську мову й окреме вікно без звичайного адресного рядка.
4. Закрийте й знову відкрийте PWA, поверніться з іншого застосунку, перевірте перехід за внутрішнім посиланням.

Актуальні назви пунктів залежать від версії Chrome. [Офіційна інструкція Google](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=uk).

### iPhone / Safari

1. Відкрийте HTTPS-адресу в Safari.
2. Відкрийте «Поділитися» через кнопку меню сторінки або панель Safari; виберіть «На початковий екран» / Add to Home Screen.
3. Якщо є перемикач Open as Web App, увімкніть його й натисніть «Додати».
4. Запустіть KidQuest із нової іконки й повторіть перевірку назви, іконки, входу та повернення з іншого застосунку.

[Офіційна інструкція Apple](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios). На iOS/iPadOS Web Push підтримується для встановлених на початковий екран вебзастосунків починаючи з 16.4; запит дозволу має бути наслідком явної дії користувача. Самої відкритої вкладки Safari для цього сценарію недостатньо. [Пояснення WebKit](https://webkit.org/blog/13878/).

## Основний сімейний сценарій

1. Зареєструвати тестового батька/матір, створити сім’ю й дитячий акаунт через передбачений UI. Увійти дитиною на іншому пристрої чи в іншому браузерному профілі.
2. Створити категорію, щоденний квест і нагороду. Перевірити порожні списки, завантаження, валідацію форм і помилку з повтором при короткому відключенні мережі.
3. Дитиною виконати квест без фото. Статус має очікувати перевірки; баланс ще не зростає.
4. Повторити з квестом, що вимагає фото. Додати JPEG, PNG або WebP з галереї/камери; перевірити орієнтацію, читабельність, перегляд батьками та ліміти до п’яти файлів по 5 МіБ. HEIC, інший непідтримуваний формат, завеликий файл або шосте фото мають дати зрозумілу відмову.
5. Батьками відхилити одне виконання й підтвердити інше. Перевірити статуси, рівно одне нарахування, історію, календар, streak і досягнення, якщо їх умови виконано. Повторне натискання/оновлення не дублює бали.
6. Дитиною запросити нагороду: сам запит не списує бали. Після підтвердження батьками баланс зменшується один раз; видача завершує запит без повторного списання. Нестача балів має бути видима.
7. Перевірити обидві теми, навігацію, профіль і локальні підказки Квестика. Інші функції працюють без зовнішнього AI.

## Офлайн і синхронізація з фото

1. Онлайн увійти дитиною, відкрити головну, квести, нагороди й історію; дочекатися індикатора збережених даних. Перший вхід без мережі не є підтримуваним сценарієм.
2. Увімкнути авіарежим і вимкнути Wi-Fi, якщо він лишився активним. Перевірити офлайн-позначку, дату останнього збереження й доступність раніше завантажених списків.
3. Зберегти виконання з фото. Має з’явитися локальна черга; баланс не змінюється. Закрити PWA, відкрити з іконки без мережі й перевірити збереження виконання та фото.
4. Відновити мережу й залишити PWA відкритим. Дочекатися автоматичного надсилання; за потреби використати «Надіслати зараз». У батьків має з’явитися одне виконання з усіма фото. Підтвердити його й перевірити одне нарахування.
5. Повторити з коротким обривом мережі під час надсилання, перезапуском PWA й двома відкритими вкладками. Дублювання виконання, фотографій або балів не допускається.
6. Окремо: зберегти офлайн-виконання, змінити квест батьками з іншого пристрою, відновити мережу дитини. Очікується явний конфлікт зі збереженими фото, можливістю повтору/скасування; програма не має мовчки переписувати умови.
7. Вийти з тестового акаунта після завершення синхронізації. При вході іншого користувача старі приватні списки та фото не показуються. Окремий тест виходу з ненадісланою чергою має враховувати, що вихід очищає цю чергу.

Фонове надсилання при повністю закритому PWA не гарантується; відновлення перевіряють після наступного відкриття. Межі й повтори описано в [phase-6.md](phase-6.md).

## Push і приватність

1. За відсутності Firebase переконатися, що UI показує «Push ще не налаштовано», а внутрішня скринька сповіщень працює.
2. На налаштованому стенді відкрити «Сповіщення», натиснути «Увімкнути push» й дозволити показ. Системний запит не має з’являтися автоматично при вході. На iPhone виконати це з установленого PWA.
3. Надіслати тестове виконання дитиною: перевірити батьківську скриньку й push у фоні. Підтвердити батьками: перевірити дитячу скриньку й push. Повторити з відкритим PWA, у фоні та після звичайного закриття; записати фактичні результати й затримку. Примусове завершення, режими енергозбереження та Focus можуть змінювати доставку.
4. На екрані блокування має бути загальний текст KidQuest без імені дитини, назв квестів, балансу чи фото. Натискання відкриває дозволену сторінку KidQuest; приватний зміст доступний після авторизації.
5. Відмовити в дозволі на окремому чистому профілі; перевірити зрозумілий стан і роботу скриньки. Повторний дозвіл надають через налаштування браузера/ОС, якщо браузер уже заблокував запит.
6. Вимкнути push у KidQuest, вийти, увійти іншою тестовою сім’єю. Нові повідомлення попереднього акаунта не повинні доставлятися цьому входу. Уже показані ОС повідомлення можуть залишатися до очищення системою.
7. Перевірити відмову в доступі до фото без входу та з іншої сім’ї. Перевірити `/storage/anything.webp`: Caddy не має публічно видавати каталог фото.

## Мобільний інтерфейс і оновлення

- На вузькому екрані й у landscape немає горизонтального прокручування; нижня навігація не перекриває кнопки й safe area.
- Екранна клавіатура не закриває активне поле та кнопку збереження; помилки доступні без точного наведення.
- Кнопки зручні для пальця, labels/фокус видимі, текст читабельний в обох темах і при збільшенні системного шрифту.
- Після згортання/розгортання стан відновлюється без повторної відправки форми; обрив API показує помилку з повтором або збережений офлайн-стан.
- Після наступної тестової збірки перевірити оновлення `/sw.js`, відкриття старої вкладки, нові lazy chunks і офлайн-перезапуск. Старі приватні дані не повинні потрапляти до публічного service worker cache.

## Фіксація результатів

26.10.2026 отримано повідомлення користувача: «все добре працює на Android та iPhone». Зафіксовано відкриття й загальну роботу на обох платформах. Після інструкції повторити офлайн-сценарій на Android та iPhone отримано відповідь «все працює»: офлайн-перезапуск, фото, синхронізація й одноразове нарахування зафіксовані як пройдені за повідомленням користувача. Моделі та версії ОС/браузерів не зазначено.

27.10.2026 після інструкції ввімкнути push на Android та iPhone користувач повідомив: «Push увімкнувся на обох телефонах». Зафіксовано успішне надання дозволу та ввімкнення push за повідомленням користувача. Це не підтверджує отримання повідомлень у відкритій, згорнутій або закритій PWA; ці сценарії залишаються неперевіреними. Кількість серверних прив’язок пристроїв цим повідомленням не підтверджується.

27.10.2026 після перевірки доставки користувач повідомив: «все працює без помилок. сповіщення приходять, на обидва пристрої». Фактичне отримання push на Android та iPhone зафіксовано як пройдене за повідомленням користувача. Точні версії ОС/браузерів, затримка та окремі результати для відкритої, згорнутої й закритої PWA не зазначені.

27.10.2026 після переходу сервера на власному ПК на постійну HTTPS-адресу Tailscale користувач підтвердив: «Так, працює на обох». Відкриття й загальна робота за новою адресою підтверджені на Android та iPhone. Моделі, версії ОС/браузерів і окреме повторне отримання системних push за новим origin у цій відповіді не зазначені.
