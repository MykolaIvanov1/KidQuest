# KidQuest на домашньому Windows-комп’ютері

KidQuest можна запускати на цьому ПК без оренди VPS. Docker зберігає базу PostgreSQL та приватні фото, а Tailscale Funnel надає постійну HTTPS-адресу для телефонів. Використовується наявний мобільний Docker-проєкт з його сімейними акаунтами, балами, фотографіями та Firebase. Нову сім’ю після перезапуску створювати не потрібно. Окрема розробницька БД із кореневого `.env` автоматично не переноситься.

План Tailscale Personal безкоштовний для особистого некомерційного використання; Funnel доступний на всіх планах. Funnel має статус beta та обмеження пропускної здатності. Це не гарантія безперервної доступності. [Тарифи Personal](https://tailscale.com/pricing), [вимоги Funnel](https://tailscale.com/docs/features/tailscale-funnel).

## Що має працювати

Для входу, синхронізації, перевірки квестів і нових push потрібні увімкнений ПК, інтернет, Docker Desktop, Tailscale та сервіси KidQuest. Tailscale на телефонах для публічного Funnel-посилання не потрібний: вони відкривають PWA у звичайному браузері.

Вимкнений екран не заважає роботі. Сон, гібернація, вимкнення ПК або зупинка Docker переривають доступ. Дитина може користуватися вже збереженими офлайн-даними, а відправлення черги продовжиться після відновлення сервера та відкриття PWA. Налаштування сну й firewall цими командами не змінюються. Цей варіант не забезпечує цілодобову роботу при вимкненому комп’ютері.

## Щоденні команди

Відкрийте PowerShell у корені репозиторію:

| Команда           | Результат                                                                                                                                    |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm pc:start`   | Відновлює наявний deployment із підготовленими образами та схваленою конфігурацією; не збирає код заново, не запускає seed і не скидає дані. |
| `pnpm pc:status`  | Перевіряє доступність і показує чинне посилання.                                                                                             |
| `pnpm pc:stop`    | Зупиняє deployment зі збереженням БД та фото.                                                                                                |
| `pnpm pc:address` | Перемикає наявний мобільний deployment на HTTPS-адресу Tailscale Funnel після входу та дозволу Funnel.                                       |
| `pnpm pc:backup`  | Створює та перевіряє узгоджену ручну копію PostgreSQL і фото.                                                                                |

Якщо PowerShell блокує shim, використовуйте `pnpm.cmd` замість `pnpm`. Поточне посилання, QR та приватна конфігурація зберігаються лише в ігнорованому `.local/mobile-preview/`. Передайте телефонам адресу, яку фактично підтвердила команда `pc:status`.

## Перехід на постійну адресу

1. Завершіть синхронізацію всіх офлайн-виконань і фото за старою адресою. Інший origin має окремі cookies, Service Worker та IndexedDB; ненадіслані фото самі між адресами не переносяться.
2. Увійдіть у встановлений Tailscale зі своїм особистим акаунтом. Підтвердьте Funnel у його офіційному вебінтерфейсі, коли він попросить дозволити публічний доступ до сервісу.
3. Із запущеним наявним KidQuest виконайте `pnpm pc:address`. Команда зберігає сімейну БД, фото та Firebase. Перебудовувати frontend для самого нового hostname не потрібно.
4. Дочекайтеся успішної перевірки HTTPS. Під час перемикання оновлюються API та web. Старий Quick Tunnel зберігається до готовності нової адреси; при помилці передбачено повернення попередньої конфігурації без видалення volumes.
5. Відкрийте нову адресу на Android та iPhone, увійдіть попередніми сімейними акаунтами, установіть PWA для цієї адреси й знову ввімкніть push. Стару іконку видаляйте після перевірки синхронізації та нового входу.

Адреса має вигляд `https://pc-name.tailnet-name.ts.net`. Вона пов’язана з іменем пристрою та мережею Tailscale: їх перейменування може змінити адресу. Funnel у режимі `--bg` відновлює поширення сервісу після перезавантаження або перезапуску Tailscale. [Стабільне ім’я Funnel](https://tailscale.com/docs/reference/examples/funnel), [фоновий запуск і перезавантаження](https://tailscale.com/docs/reference/tailscale-cli/funnel).

Web публікується тільки на loopback `127.0.0.1:5188` для локального Tailscale-проксі. Це не відкриває порт у локальну мережу; PostgreSQL та API не мають host-портів. Публічна Funnel-адреса дозволяє відкрити сторінку входу через інтернет, а доступ до сімейних даних далі контролює авторизація KidQuest.

## Автозапуск після входу у Windows

```powershell
pnpm pc:startup prepare
pnpm pc:startup install
pnpm pc:startup status
```

`prepare` готує `.local/pc-host/startup-task.xml` і `startup-task.json` для перегляду, не реєструючи завдання. `install` реєструє власне завдання цього checkout у Планувальнику Windows. Завдання належить поточному користувачу, використовує `InteractiveToken` і `LeastPrivilege`, не зберігає пароль і не запускається як SYSTEM. Інше завдання з конфліктним ім’ям не перезаписується.

Запуск відбувається **після входу цього користувача у Windows**, а не до екрана входу. Runner за потреби запускає Docker Desktop приховано, очікує готовності рушія до десяти хвилин та викликає `pc:start`. Папку KidQuest і встановлений Node.js потрібно залишити на місці; перед перенесенням checkout приберіть його попередній автозапуск.

Перевірити runner вручну або прибрати лише автозапуск:

```powershell
pnpm pc:startup run
pnpm pc:startup remove
```

`run` справді відновлює deployment. `remove` прибирає тільки власне завдання Windows, зберігаючи дані KidQuest. Команди реєстрації потребують відповідних дозволів Windows; при помилці доступу перевірка зупиняється без підміни чужих завдань. Результат останнього запуску та обмежений журнал зі службовими статусами знаходяться в `.local/pc-host/`; секретні env-значення й повні відповіді дочірніх процесів до них не записуються.

## Резервні копії

```powershell
pnpm pc:backup
```

Команда бере блокування операції, тимчасово зупиняє API для узгодженості БД і фото та після спроби повертає API до попереднього стану. Під час паузи вхід і синхронізація можуть бути недоступні. У `.local/backups/` створюється новий каталог із `database.dump`, `photos/` і `manifest.json`; перевіряються формат архіву та SHA256. Старі копії не перезаписуються. Це ручне копіювання, а не автоматичний розклад.

Зберігайте перевірену копію також поза диском цього ПК із захистом доступу. Копії містять приватні дані та хеші паролів. Не додавайте `.local/`, env-файли, Firebase Admin JSON або ключі до Git. Перевірка manifest не замінює пробного відновлення; деталі — у [backup.md](backup.md).

## Стан перевірки 27.10.2026

Tailscale 1.104.2 встановлено, користувач увійшов і явно підтвердив Enable Funnel. Команда `pc:address` успішно перевела наявний deployment на стабільну HTTPS-адресу Tailscale зі збереженням тієї самої БД, фотографій та Firebase. Поточний hostname не записують у Git; його показує `pc:status`.

Через нову публічну HTTPS-адресу перевірено готовність сервісу, захист `/notifications/status` без авторизації та `pushConfigured: true` після входу. У 31 публічному JavaScript-файлі перевірено відсутність серверного приватного ключа й серверної email-адреси. Це програмні перевірки конфігурації, які не підтверджують показ push на фізичному телефоні.

Команда `pc:backup` створила та перевірила справжню резервну копію наявної БД і фото у `.local/backups/`. Перевірено архів і контрольні суми; це не новий тест відновлення цієї копії.

Власне завдання автозапуску цього checkout встановлено у Планувальнику Windows. Перший запуск завдання на вимогу завершився READY у попередньому режимі Quick Tunnel. Повторний запуск на вимогу після переходу на Funnel завершився READY. Додатково контрольовано зупинено лише API та web: завдання Windows відновило обидва сервіси без зміни постійної адреси. Вхід попереднього синтетичного дитячого акаунта, початкові IDs журналу, точний баланс і SHA256 старого фото збережені. Справжнє перезавантаження Windows і подальший запуск за подією входу користувача цими перевірками не підтверджені. Фактичний стан завдання перевіряє `pc:startup status`.

Перевірка живлення показала таймер `STANDBYIDLE`: від електромережі — 0 (автоматичний сон за цим таймером вимкнений), від акумулятора — 240 секунд. Налаштування живлення не змінювалися. Робота від батареї, закриття кришки, гібернація або вимкнення ПК можуть перервати доступ незалежно від автозапуску.

Мобільні встановлення, офлайн-сценарій і доставка Firebase push на Android та iPhone за попередньою адресою підтверджені користувачем 27.10.2026. 27.10.2026 після інструкції перейти на постійну адресу, ввійти, встановити PWA та ввімкнути push користувач відповів: «Так, працює на обох». Роботу постійної адреси на Android та iPhone підтверджено за повідомленням користувача. Окреме повторне отримання системного push саме за новою адресою та детальні стани PWA цією відповіддю не підтверджуються; результати фіксуються в [mobile-qa.md](mobile-qa.md).

Перевірки інструментів: 58 тестів пройдено, один тест symlink пропущено через обмеження Windows. ESLint, Prettier та diff check успішні. Усі зміни цього блоку стосуються host tooling і документації; користувацький код застосунку не змінювався.
