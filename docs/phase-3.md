# Гейміфікація, календар і прогрес

Реалізовано блок 047–050 з ТЗ: автоматичні досягнення, серії днів, календар та статистика. Нові розділи доступні обом ролям; дитина переглядає власні результати, батьки — результати дитини своєї сім’ї. UI першої версії використовує першу активну дитину; API приймає явний `childId` для батьків.

## Серія днів

День зараховується до серії, якщо є хоча б одне підтверджене виконання й підтверджені всі обов’язкові квести цього дня. Сам день без завдань не збільшує серію. Якщо сьогоднішній день ще не завершено, показується серія, яка закінчилася вчора. Пропущений минулий день перериває послідовність. Майбутні дні ігноруються.

Обчислення використовує календарні дати в часовій зоні сім’ї та враховує перехід на літній/зимовий час. Дата виконання визначається сервером. Пізнє підтвердження батьками змінює результат початкового дня виконання та може відновити історичну серію. Окремо обчислюється найкраща серія.

## Історія розкладу

Міграція `20261023000000_gamification_history` додає `TaskScheduleVersion`. Створення, зміна та видалення квесту транзакційно зберігають знімок його назви, обов’язковості, повторення, активності та дат від поточного дня сім’ї. Попередні дні зберігають свої умови. Зміни в межах одного дня оновлюють сьогоднішню версію. Календар зберігає фактичні виконання навіть після soft delete завдання.

Для квесту без повторення минуле підтвердження завершує його подальші очікування. При виправленні відхиленого квесту іншого дня ID виконання зберігається за контрактом попереднього етапу; минуле відхилення відновлюється з аудиту й показується без посилання на поточні фото.

**Для наявної бази достовірне відстеження умов починається в день цієї міграції.** Старі виконання та зароблені бали відображаються, але старі пропуски й серії до початку відстеження не вигадуються. API повертає `trackingFrom`. Нові діти починають відстеження не раніше дати створення їхнього профілю.

## Досягнення

Довідник доступний після міграції без запуску seed із паролями:

| Код          | Умова                                         |
| ------------ | --------------------------------------------- |
| `STREAK_7`   | Найкраща підтверджена серія щонайменше 7 днів |
| `TASKS_30`   | 30 підтверджених виконань                     |
| `POINTS_100` | 100 балів за підтверджені завдання            |
| `POINTS_500` | 500 балів за підтверджені завдання            |

Відзнака записується в `UserAchievement` у тій самій транзакції, що й підтвердження та бали. Унікальність користувача й досягнення захищає від дублювання при повторних або конкурентних запитах. Перегляд підсумку також дозараховує відзнаки за фактичною попередньою історією. Отримані відзнаки зберігаються; витрачання балів на нагороди їх не забирає.

Зароблені бали — сума додатних `TASK_REWARD`, пов’язаних із підтвердженими виконаннями не пізніше поточного дня сім’ї. Бонуси та списання не змінюють цей показник. Для календаря бали відносяться до дати виконання, навіть коли батьки перевірили його пізніше.

## API та екрани

Усі маршрути мають префікс `/api/v1` та потребують bearer-авторизації.

| Метод і маршрут                                       | Результат                                                   |
| ----------------------------------------------------- | ----------------------------------------------------------- |
| `GET /achievements?childId=UUID`                      | Отримані й доступні досягнення, прогрес, найближча відзнака |
| `GET /calendar?month=YYYY-MM&childId=UUID`            | Календар місяця та виконання кожного дня                    |
| `GET /statistics/progress?month=YYYY-MM&childId=UUID` | Календар, статистика місяця, серії та підсумки за весь час  |
| `GET /statistics`                                     | Головна панель із реальною серією й `gamification`          |

`month` необов’язковий: типовий місяць визначається за часовою зоною сім’ї. Перевіряються формат, реальний місяць і UUID дитини. Дитині заборонено передавати ID іншої дитини. Майбутні дні повертаються без виконань і балів. Стани виконань показують очікування, підтвердження, відхилення та пропуск; вибір дня відкриває його перелік квестів. Графік має доступне текстове представлення.

Шляхи UI: `/child/achievements`, `/child/calendar`, `/parent/achievements`, `/parent/statistics`. Дані оновлюються після перевірки квестів і при зміні дня. Підтримуються світла й темна теми, вузький екран, стани завантаження, помилки, повторного запиту та відсутності дитини.

## Запуск і перевірки

На Windows у корені репозиторію:

```powershell
pnpm db:generate
pnpm db:deploy
pnpm dev
```

Перевірки: `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm test`, `pnpm db:test`, `pnpm build`. Інтеграції та перевірки обмежень використовують окрему `DATABASE_TEST_URL`; сімейна база не використовується для тестових записів.

Основні зміни: `prisma/schema.prisma` і нова міграція, `packages/types`, `backend/src/modules/gamification`, історичні знімки в модулі tasks, інтеграція підтвердження та dashboard; нові frontend-сторінки, навігація, підсумок на головній панелі та тести.

Перевірено 22 жовтня 2026 року: 196 тестів (42 спільної валідації, 55 frontend, 99 backend), 7 перевірок обмежень PostgreSQL, Prisma validate, strict TypeScript, ESLint, Prettier, production build та `git diff --check`. Новий блок має 13 unit-тестів обчислень, 15 інтеграційних HTTP-тестів і 11 перевірок UI, включно зі старими виконаннями без відомого початкового розкладу.

У браузері в окремій тестовій сім’ї перевірено календар, вибір дня, перемикання місяця, доступну таблицю графіка та обидві ролі. Підтвердження останнього обов’язкового квесту збільшило серію з 6 до 7 днів, баланс зі 115 до 125 і автоматично відкрило `STREAK_7`. Перевірено світлу й темну теми та ширину 320 px без горизонтального переповнення. Сімейні записи користувача не використовувались як тестові дані.

Наступні блоки ТЗ: сповіщення FCM, розширення налаштувань акаунтів, повна офлайн-синхронізація та AI. Встановлення PWA на фізичний телефон потребує окремої перевірки.
